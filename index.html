Authentication

All endpoints (except 1.1 Login) require a valid JWT access token in the Authorization header:

Authorization: Bearer <access_token>

1. Authentication

1.1 Login

POST /login/

Broker login with email and password. Returns JWT access and refresh tokens plus broker user details.

Request Body (JSON):

FieldTypeRequiredDescription
emailstringYesBroker registered email
passwordstringYesBroker password

Success Response (200 OK):

{
  "status_code": 200,
  "message": "Login successful",
  "data": {
    "user": {
      "id": 1,
      "first_name": "John",
      "last_name": "Doe",
      "email": "broker@example.com",
      "is_broker": true,
      "broker_fra_id": "FRA-123",
      "broker_status": "individual",
      "broker_data_confirmed": true
    },
    "credentials": {
      "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
      "refresh_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
    }
  }
}

Error Responses:

StatusCause
400email and/or password missing or malformed
401Invalid credentials, account inactive, or user not found
403User is not a broker or broker data is not confirmed

2. Broker Bank Details

Bank details must be submitted and approved before a commission can be paid out. The authenticated broker can retrieve their current details or submit new ones. A stamped bank details PDF is required on first submission.

2.1 Get Bank Details

GET /bank-details/

Returns the broker's current bank details. If no details have been submitted yet, an empty payload is returned without creating a database row.

Headers: Authorization: Bearer <access_token>

Success Response (200 OK) — existing details:

  "bank_name": "CIB",
  "bank_branch_name": "Mohandeseen",
  "account_name": "John Doe Broker Account",
  "account_number": "1234567890",
  "swift_code": "CIBEGCXA",
  "iban": "EG000000000000000000000000",
  "has_stamped_bank_details": true,
  "status": "pending",

2.2 Add / Update Bank Details

POST /bank-details/

Submit or resubmit the broker's bank details. On first submit a new row is created; on subsequent submits the existing row is updated and its status is reset to pending for re-approval. A stamped bank details PDF must be supplied.

Headers:

HeaderValue
AuthorizationBearer <access_token>
Content-Typemultipart/form-data

Request Body (multipart/form-data):

FieldTypeRequiredDescription
bank_namestringYesBank name (must match an active Egyptian bank)
account_namestringYesAccount holder name
account_numberstringYesBank account number
bank_branch_namestringNoBranch name
swift_codestringNoSWIFT code
ibanstringNoIBAN
stamped_bank_detailsfileYesStamped bank details PDF

Success Response (201 Created on first submit, 200 OK on resubmit):

{
  "id": 7,
  "bank_name": "CIB",
  "account_name": "John Doe Broker Account",
  "account_number": "1234567890",
  "status": "pending",
  "status_display": "Pending Approval",
  "is_editable": true,
  "exists": true
}

Error Responses:

StatusCause
400Missing required fields, invalid bank name, or non-PDF stamped file
400Broker FRA ID is required before submitting bank details
400Approved bank details cannot be changed (use resubmit flow)

Note: Use PATCH /bank-details/ to update an existing row partially. Approved bank details cannot be changed directly; resubmit via POST instead.

3.3 Upload E-Invoice

POST /commissions/{id}/upload-e-invoice/

Upload the E-Invoice PDF for a commission. The uploaded file is saved and then passed to BrokerCommissionService.record_e_invoice_upload, which runs the KAF AI matching check and updates the commission status automatically.

Headers:

HeaderValue
AuthorizationBearer <access_token>
Content-Typemultipart/form-data

Path Parameter:

ParamTypeDescription
idintegerCommission ID

Request Body (multipart/form-data):

FieldTypeRequiredDescription
e_invoicefileYesE-Invoice PDF file

Success Response (200 OK):

{
  "message": "E-Invoice approved by KAF AI.",
  "commission": {
    "id": 42,
    "status": "awaiting_signed_voucher",
    "status_display": "Awaiting Signed Voucher",
    "has_e_invoice": true,
    "can_upload_e_invoice": false
  },
  "ai_check": {
    "decision": "matched",
    "decision_display": "Matched",
    "reasoning": "The e-invoice figures match the expected commission amounts.",
    "rejection_reason": ""
  }
}

Status transitions after upload:

  • If bank details are pending/rejected, the file is stored but status stays unchanged.
  • Otherwise the commission moves to e_invoice_uploaded, the AI check runs, and the status becomes:
    • awaiting_signed_voucher when the E-Invoice is matched
    • rejected when the E-Invoice is mismatched, with rejection_reason populated

Error Responses:

StatusCause
400No E-Invoice file provided or commission status does not allow upload
404Commission not found or does not belong to the broker

Commission Status Flow

The commission lifecycle for broker payouts.

StatusDescription
pending_bank_details_approvalCommission is created but broker bank details are not approved yet
bank_details_rejectedBank details were rejected; resubmit bank details to proceed
e_invoice_uploadedE-Invoice uploaded, pending AI verification
rejectedE-Invoice did not pass AI validation; re-upload after fixing
awaiting_signed_voucherE-Invoice approved; broker must upload signed voucher next
approved_for_paymentCommission approved and queued for payment
paidPayment completed

Workflow Summary

Typical broker journey for managing commissions.

Login1.1 — obtain access_token
Add Bank Details2.2 — submit stamped PDF, wait for approval
List Commissions3.1 — view all commissions and statuses

Upload E-Invoice3.3 — AI matching runs and status updates automatically
